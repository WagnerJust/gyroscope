# ADR 0020: cross-harness MCP, and the dedicated-vs-shared file-ownership split

- **Status:** accepted
- **Date:** 2026-08-24

## Context

MCP servers are declared per harness in incompatible ways (research 2026-08-24):
Claude uses a dedicated `.mcp.json` with `mcpServers` + stdio/http; OpenCode uses a
`mcp` key inside its shared `opencode.json` with `local/remote`, a merged command
array, and `environment` (not `env`). The inner per-server entries are NOT
byte-portable — field names, the type enum, and the command shape all differ. So MCP
needs a neutral canonical model re-encoded per harness, like personas and commands.

Two second-order problems:

- **Where does the canonical declaration live?** Not a doc file — MCP is structured
  config. `gyroscope.json` is its natural home.
- **Secrets.** MCP servers carry API keys. gyroscope must not commit or bake raw
  secrets.
- **File ownership differs by harness.** Claude's `.mcp.json` is a dedicated file
  gyroscope can own whole; OpenCode's config is shared with the user's other settings
  (and, since ADR-0006's OpenCode injection, gyroscope's own `instructions`).

## Decision

- **Neutral declaration** in `gyroscope.json` `mcp`: `{name: {command,args,env}}`
  (stdio/local) or `{name: {url,headers}}` (remote), discriminated by `command` vs
  `url`. `internal/mcp` re-encodes it deterministically (sorted keys) into each
  harness's shape, so `check` verifies byte-for-byte.
- **Secrets never raw.** Values reference `${ENV_VAR}` only; gyroscope passes them
  through verbatim (HTML-escaping off) and every target expands env vars at runtime.
  This keeps the generated configs safe to commit and to bake into `gyroscope-sync.sh`.
- **File ownership split by the tool's own layout:**
  - *Dedicated files* gyroscope owns whole — Claude `.mcp.json` (and PI `.pi/mcp.json`
    later). Generated from the declaration, so they ride the `planMirrors`
    generated-file list: written by init, verified byte-for-byte by `check`,
    regenerated by `check --fix`, gitignorable, and baked into the sync script.
    Owning them whole means a server removed from `gyroscope.json` disappears from the
    file on the next run.
  - *Shared config merged in place* — OpenCode `opencode.json` `mcp`. gyroscope merges
    its declared servers by name (via the settings read-modify-write), preserving the
    user's other `mcp` entries and top-level keys, and `check` verifies each declared
    server matches after JSON normalization. Trade-off: a server removed from
    `gyroscope.json` is NOT pruned from the shared file (gyroscope only owns the names
    it currently declares) — a documented shared-config limitation the dedicated files
    do not have.

## Consequences

- A team declares MCP servers once in `gyroscope.json` and every enabled harness gets
  them in its own format — the "author once, works everywhere" story extends to MCP.
- The dedicated/shared split is principled (driven by each tool's file layout, not an
  arbitrary choice) and reuses machinery gyroscope already has: the mirror pipeline
  for dedicated files, the settings-merge for shared config.
- `${VAR}`-only keeps secrets out of git and out of the baked sync script; the "no raw
  secrets" rule is a documented convention, not enforced by gyroscope.
- PI MCP is deliberately absent here — it has no native MCP and reaches it only via a
  generated client extension, a separate, later, droppable phase.
